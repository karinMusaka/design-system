# 0001 — カラーパレット採用

Status: Accepted
Date: 2026-03-05

## Context

複数プロジェクト（biz-buddy, life-protocol, mission-control 等）で UI トーンがバラバラだった。共通の視覚言語を確立することで:
- スイッチングコストを下げる
- 制作物（スライド/PDF/ダッシュボード）に一貫性を持たせる
- agent が判断に迷わない明確なトークンを提供する

参照: Marathon (Bungie 2025) のキービジュアル — 純黒 + ネオンライム + シャープなインダストリアル質感。

## Decision

主要トークン:

| Token | Value | 役割 |
|-------|-------|------|
| `background` | `#000000` | 全画面の基底。**純黒**を維持し `#111` 系で薄めない |
| `surface` | `#222222` | カード・パネル。背景から1ステップ浮かせる用途のみ |
| `surface-alt` | `#1C1C1C` | コードブロック・補助面 |
| `text` | `#FFFFFF` | 本文 |
| `text-muted` / `text-dim` | `#999999` / `#666666` | 二次情報 |
| `accent` | `#C0FE04` | **唯一の強調色**。CTA・リンク・強調・ブランド |
| `accent-hover` | `#D4FF4D` | accent のホバー（同系統で明るく） |
| `warning` | `#FF5500` | 注意喚起。**赤ではなくオレンジ**で「危険」と区別 |
| `error` | `#FF3333` | 致命的エラーのみ。氾濫させない |
| `info` | `#3860BE` | 情報の二次強調 |
| `success` | `#00CC66` | 完了状態 |

## Why これらの値か

### `#C0FE04`（ネオンライム）
- **CRT モニタ的彩度**：純黒背景でも目に焼き付くハイトーン
- 蛍光緑 (`#00FF00`) より黄みを帯びていて、Marathon 的ミリタリー/インダストリアル雰囲気が出る
- shadcn/ui や OpenAI などの汎用デザインで使われない希少な色相 → ブランド識別性

### `#000000` 純黒
- OLED 親和（節電 + コントラスト）
- 「シャープさ」の必須要件。`#0A0A0A` でも妥協しない
- `surface` `#222222` との明度差で階層が立つ

### Warning `#FF5500` を「赤」にしなかった理由
- `error` 用の純赤 `#FF3333` と視覚的に区別する必要があった
- オレンジは「警告」「注意」の心理メッセージを残しつつ、accent ライムと色相環で90度離れて並置可能

## Consequences

- 他社プロダクトと**ぱっと見で見分けがつく**（ネオンライムが識別子）
- ライト/明色背景のプロジェクトには使えない → 必要なら別テーマを分岐
- accent を多用すると視覚疲労 → コンポーネント側で「accent は1画面1〜2箇所」のガイドラインを別途運用
